# KLINK نسخه‌ی ۱

هسته‌ی پروکسی رمزنگاری‌شده و پنل مدیریت وب برای Ubuntu، پیاده‌شده با Go و بدون CGO. مخزن شامل سرور UDP/TCP، نشست‌های Noise_XK، مهاجرت شبکه، مالتی‌پلکس TCP/UDP، دیتابیس SQLite، کاربران حجمی و زمانی، لینک اشتراک و داشبورد زنده است.

> **توجه‌ی امنیتی:** KLINK یک پیاده‌سازی جدید پروتکل است و هنوز ممیزی امنیتی مستقل نشده است. پیش از استفاده‌ی گسترده‌ی عملیاتی، ممیزی رمزنگاری و فازینگ انجام دهید. هیچ پروتکلی را نمی‌توان «تضمیناً غیرقابل‌شناسایی» دانست. پروفایل `tls-mimic` فقط رکوردهای Application Data را می‌سازد و فینگرپرینت کامل ClientHello یا رفتار مرورگر را تقلید نمی‌کند.

## امکانات

- الگوی `Noise_XK` با X25519 و کلید عمومی ازپیش‌شناخته‌شده‌ی سرور.
- ChaCha20-Poly1305، BLAKE2s و HKDF؛ کلیدهای مستقل برای دو جهت.
- SessionID تصادفی ۱۲۸بیتی و مهاجرت آدرس یا UDP/TCP پس از احراز بسته.
- توالی ۶۴بیتی، پنجره‌ی anti-replay به اندازه‌ی ۱۰۲۴ بسته و rekey خودکار.
- قاب‌بندی TCP با طول ماسک‌شده‌ی وابسته به شمارنده؛ رمزنگاری اصلی در لایه‌ی AEAD.
- پروفایل‌های `random` و `tls-mimic` و رهاسازی بی‌صدا‌ی بسته‌های نامعتبر.
- مالتی‌پلکس چند جریان TCP و چند UDP association روی یک نشست.
- محدودیت حجم، انقضا و تعداد نشست/دستگاه هم‌زمان برای هر کاربر.
- لینک اشتراک با توکن ۲۵۶بیتی و JSON شامل کلیدها و endpointها.
- پنل فارسی RTL با Tailwind CSS، آمار آنلاین، پورت‌ها و مدیریت کامل کاربران.
- SQLite با WAL، بدون CGO، systemd و UFW.
- کلاینت Android با `VpnService` و TUN واقعی، هسته‌ی gomobile، عبور TCP/UDP و ذخیره‌ی اشتراک با Android Keystore.

راهنمای نصب، معماری و ساخت کلاینت در [`docs/ANDROID.md`](docs/ANDROID.md) آمده است.

```text
│   ├── session/                # handshake، migration، quota و آمار
│   ├── mux/                    # جریان‌های TCP و UDP association
│   └── store/                  # schema و عملیات SQLite
├── web/                        # رابط مدیریت Tailwind
├── configs/                    # نمونه‌ی کانفیگ سرور و پنل

├── install.sh                  # نصب کامل Ubuntu
└── go.mod / go.sum
```

## نصب سریع روی Ubuntu

فقط همین یک دستور را روی سرور (با کاربر root) اجرا کنید:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/kankiturk8770/klink/main/install.sh)
```

نصب‌کننده می‌پرسد:

```text
Do you have a domain (A record) pointing to this server? / دامنه دارید؟ [y/N]:
```

- اگر `y` بزنید، دامنه را می‌پرسد، بررسی می‌کند که واقعاً به IP همین سرور اشاره کند و **خودش گواهی SSL از Let's Encrypt می‌گیرد**؛ پنل روی `https://دامنه:8080` بالا می‌آید و گواهی خودکار تمدید می‌شود.
- اگر `n` بزنید، پنل با IP سرور و گواهی self-signed روی HTTPS بالا می‌آید. برنامه‌ی اندروید این گواهی را از طریق اثر انگشتی که داخل لینک اشتراک است می‌شناسد، پس لینک بدون دامنه هم کار می‌کند.

هیچ فایلی لازم نیست ویرایش شود. نسخه‌ی آماده (بدون نیاز به Go) از بخش Releases گیت‌هاب دانلود می‌شود. اسکریپت این کارها را انجام می‌دهد:

1. دانلود آخرین نسخه‌ی آماده؛ اگر Release وجود نداشته باشد، کد را دانلود و با Go می‌سازد.
2. ساخت کلید سرور، توکن API داخلی و رمز تصادفی ادمین.
3. ساخت `/etc/klink` و `/var/lib/klink`.
4. پرسیدن دامنه و فعال‌کردن SSL خودکار (یا self-signed).
5. بازکردن همه‌ی پورت‌های واقعی SSH، پنل، پورت ۸۰ برای Let's Encrypt و پورت UDP/TCP پروکسی در UFW.
6. نصب و اجرای `klink-core.service` و `klink-panel.service` با sandbox سخت‌گیرانه‌ی systemd.
7. گرفتن اولین گواهی و بررسی اینکه HTTPS پنل کار می‌کند.

اطلاعات ورود در پایان نمایش داده می‌شود و فقط برای root در فایل زیر نیز ذخیره می‌شود:

```text
/root/klink-credentials.txt
```

تنظیمات اختیاری پیش از نصب:

```bash
sudo \
  DOMAIN=vpn.example.com \
  ACME_EMAIL=admin@example.com \
  PROXY_PORT=443 \
  PANEL_PORT=8080 \
  SSH_PORT=22 \
  ADMIN_USERNAME=admin \
  bash install.sh
```

| متغیر | توضیح |
|---|---|
| `DOMAIN` | دامنه‌ی سرور برای SSL خودکار و endpoint پروکسی |
| `ACME_EMAIL` | اختیاری؛ ایمیل هشدار انقضای Let's Encrypt |
| `SSL_MODE` | `auto` (پیش‌فرض)، `acme`، `selfsigned` یا `off` |
| `FORCE_ACME=1` | درخواست گواهی حتی اگر بررسی DNS رد شود |
| `PUBLIC_HOST` | اگر endpoint پروکسی با دامنه‌ی پنل فرق دارد |

برای نصب بدون سؤال، متغیرها را از قبل بدهید (مثلاً `DOMAIN=vpn.example.com`) یا `NONINTERACTIVE=1` بگذارید. اجرای دوباره‌ی اسکریپت باینری‌ها را ارتقا می‌دهد، اما کانفیگ، کلید سرور و رمز ادمین موجود را حفظ می‌کند. برای اینکه نصب قدیمیِ HTTP به HTTPS برود، اسکریپت را دوباره با `DOMAIN=...` (یا `SSL_MODE=selfsigned`) اجرا کنید. توجه کنید که آدرس پنل و لینک‌های اشتراک از `http://` به `https://` تغییر می‌کند.

### HTTPS پنل

نصب‌کننده HTTPS را خودکار فعال می‌کند. تنظیمات مربوط در `/etc/klink/panel.json`:

```json
{
  "public_url": "https://vpn.example.com:8080",
  "acme_domain": "vpn.example.com",
  "acme_email": "",
  "acme_cache_dir": "/var/lib/klink/acme",
  "acme_http_listen": ":80"
}
```

- با `acme_domain`، خود پنل گواهی Let's Encrypt را می‌گیرد و تمدید می‌کند (بدون certbot و cron). اعتبارسنجی HTTP-01 روی پورت ۸۰ است و همان پورت بقیه‌ی درخواست‌ها را به HTTPS هدایت می‌کند؛ بنابراین پورت ۸۰ باید باز و آزاد بماند.
- به‌جای ACME می‌توان گواهی دلخواه داد: `tls_cert_file` و `tls_key_file`.
- با فعال‌بودن TLS، کوکی مدیریت همیشه `Secure` و با پیشوند `__Host-` است و HSTS ارسال می‌شود.
- اگر دامنه پشت CDN (مثلاً Cloudflare با ابر نارنجی) باشد، بررسی DNS رد می‌شود؛ یا CDN را برای این رکورد خاموش کنید یا `FORCE_ACME=1` بدهید.

پس از تغییر دستی کانفیگ، `sudo systemctl restart klink-panel` را اجرا کنید و خطاها را با `journalctl -u klink-panel -e` ببینید.

## ساخت کاربر و اتصال کلاینت

1. وارد پنل شوید و **ساخت کاربر** را بزنید.
2. حجم را برحسب GB وارد کنید؛ صفر یعنی نامحدود.
3. تعداد دستگاه صفر یعنی نامحدود؛ مقدار یک، فقط یک نشست هم‌زمان می‌پذیرد.
4. تاریخ انقضا اختیاری است.
5. پس از ذخیره، **نمایش لینک** را بزنید و لینک یا JSON را در اختیار همان کاربر بگذارید.

نمونه‌ی مسیر اشتراک:

```text
https://panel.example.com/sub/<43-character-random-token>
```

پاسخ JSON شامل `client_private_key`، `client_public_key`، `server_public_key`، فهرست `transports`، پروفایل obfuscation و تنظیمات rekey است. کلاینت موبایل باید این فایل را با HTTPS و `Cache-Control: no-store` دریافت کند. قالب دقیق بسته‌ها در `docs/PROTOCOL.md` آمده است.

اگر لینک افشا شد، عملیات **چرخش توکن** لینک قبلی را بی‌اعتبار می‌کند. کلید خصوصی کلاینت تغییر نمی‌کند. برای ابطال کامل دسترسی، کاربر را غیرفعال یا حذف کنید؛ هسته در بررسی دوره‌ای، حداکثر تقریباً ظرف یک دقیقه، تغییر را روی نشست‌های قبلی نیز اعمال می‌کند.

## اجرای دستی برای توسعه

به Go 1.26 یا جدیدتر نیاز است.

```bash
go mod download
go test ./...
go build ./cmd/server ./cmd/panel
```

کلید سرور بسازید:

```bash
go run ./cmd/server -genkey
```

رمز مدیریت را هش کنید:

```bash
KLINK_PASSWORD='a-long-random-password' go run ./cmd/panel -hash-password
```

دو فایل `configs/server.example.json` و `configs/panel.example.json` را کپی و مقداردهی کنید. مقدار `status_token` در سرور باید با `core_status_token` در پنل یکی باشد. سپس:

```bash
go run ./cmd/server -config /path/to/server.json
go run ./cmd/panel -config /path/to/panel.json
```

برای اجرای محلی، `web_root` را `web` و `public_url` را آدرس پنل قرار دهید.

## عملیات و عیب‌یابی

```bash
systemctl status klink-core klink-panel
journalctl -u klink-core -f
journalctl -u klink-panel -f
curl http://127.0.0.1:9091/healthz
```

- **پنل «هسته خارج از دسترس» می‌گوید:** اجرای core، توکن مشترک و آدرس `127.0.0.1:9091` را بررسی کنید.
- **کاربر ساخته می‌شود ولی وصل نمی‌شود:** کلید عمومی سرور، endpoint عمومی، بازبودن UDP/TCP در فایروال و حجم/انقضا را بررسی کنید.
- **اتصال پس از تغییر Wi-Fi/دیتا قطع می‌شود:** کلاینت باید همان SessionID و کلیدها را از مسیر جدید ادامه دهد؛ handshake جدید لازم نیست.
- **دستگاه دوم پذیرفته نمی‌شود:** مقدار device limit و نشست قبلی آنلاین را بررسی کنید. برنامه هنگام قطع، نشست را روی سرور می‌بندد؛ نشستی هم که بیش از ۴۵ ثانیه بسته‌ای نفرستاده باشد (مثلاً گوشی خاموش شده) با اتصال تازه‌ی همان کاربر جایگزین می‌شود.
- **گواهی SSL گرفته نمی‌شود:** رکورد A دامنه، بازبودن پورت ۸۰ (در فایروال سرور و دیتاسنتر) و `journalctl -u klink-panel -e` را بررسی کنید.
- **حجم بلافاصله در SQLite دیده نمی‌شود:** هسته مصرف را تجمیع و هر ده ثانیه ذخیره می‌کند؛ داشبورد مقدار زنده را از core می‌گیرد.

## تست و بررسی

```bash
go test -race ./...
go vet ./...
```

تست‌ها شامل Noise_XK، تبادل دوجهته، rekey، عدم تخریب نشست با بسته‌ی جعلی، replay، بسته‌ی دیررسیده‌ی epoch قبلی، round-trip هر دو obfuscation، framing با ارتقای ماسک، handshake واقعی UDP و TCP، ارسال دوباره‌ی ACK گم‌شده، جایگزینی نشست مرده در محدودیت دستگاه، مهاجرت آدرس و مهاجرت به TCP با قاب‌های پشت‌سرهم، TCP/UDP mux، مسدودسازی مقصدهای داخلی، سقف جریان‌ها، SQLite، API مدیریت/اشتراک، محدودیت حدس رمز و CSRF هستند.

## نکات امنیتی و محدودیت‌های نسخه‌ی ۱

- کلیدهای خصوصی صادرشده برای اشتراک در SQLite نگه داشته می‌شوند تا پنل بتواند JSON را دوباره ارائه کند. از دیتابیس و backupها محافظت کنید. برای مدل امنیت بالاتر می‌توان در نسخه‌ی بعد فقط کلید عمومی را روی سرور نگه داشت و تولید کلید را به دستگاه کاربر منتقل کرد.
- رمز عبور ادمین با bcrypt بررسی می‌شود؛ کوکی `HttpOnly` و `SameSite=Strict` است و mutationها به header اختصاصی نیاز دارند.
- پاسخ به بسته‌ی خراب، replay یا کاربر ناشناخته ارسال نمی‌شود. لاگ‌ها نیز بسته‌ی خام را چاپ نمی‌کنند.
- obfuscation جای رمزنگاری را نمی‌گیرد. `tls-mimic` یک TLS stack واقعی یا uTLS نیست و نباید به‌عنوان تضمین عبور از DPI معرفی شود.
- rekey بدون handshake جدید انجام می‌شود؛ گیرنده یک پنجره‌ی replay جدا برای epoch قبلی نگه می‌دارد تا بسته‌های دیررسیده‌ی UDP پس از rekey دور ریخته نشوند.
- کاربران پروکسی به loopback سرور (مثل API وضعیت و پنل)، link-local (مثل 169.254.169.254 سرویس metadata ابری)، multicast و شبکه‌های خصوصی دسترسی ندارند. بررسی پس از resolve شدن DNS انجام می‌شود. برای اجازه به شبکه‌های خصوصی در `server.json` مقدار `"allow_private_destinations": true` بگذارید.
- هر نشست حداکثر ۱۰۲۴ جریان هم‌زمان، هر IP حداکثر ۶۴ handshake نیمه‌کاره و سرور حداکثر ۳۲۷۶۸ اتصال TCP هم‌زمان دارد. اتصال TCP که ظرف ۳۰ ثانیه handshake نکند بسته می‌شود.
- ورود ادمین در برابر حدس موازی رمز محدود است (۵ تلاش، سپس ۱۵ دقیقه مسدود) و درخواست‌های تغییر از origin دیگر رد می‌شوند. Tailwind به‌صورت فایل محلی است و هیچ اسکریپت شخص ثالثی در پنل اجرا نمی‌شود.
- **محدودیت طراحی:** لایه‌ی mux روی انتقال UDP، تحویل مطمئن و مرتب ندارد. اگر بسته‌ای روی UDP گم شود یا جابه‌جا برسد، داده‌ی یک جریان TCP داخل تونل خراب می‌شود. تا افزوده‌شدن لایه‌ی reliable در نسخه‌ی بعد، کلاینت باید جریان‌های TCP را روی انتقال TCP و فقط associationهای UDP را روی انتقال UDP بفرستد. سرور برای کاهش آسیب، داده‌ی TCP روی مسیر UDP را در قطعه‌های کوچک‌تر از MTU می‌فرستد.
- برای production از HTTPS پنل، backup رمزشده، محدودسازی دسترسی SSH و به‌روزرسانی سیستم استفاده کنید.
